# 试听样本

全部由 `src/api_server.py` 现场合成。每段音频用两个识别器回读：
`base` = 原版 SenseVoiceSmall（普通话），`ft` = 川话微调版。

回读 CER 的读法很关键：**CER 低 ≠ 口音好**。川话口音会让普通话识别器写出别的字，
CER 反而升高；但如果是合成崩了，川话识别器也救不回来，两个 CER 会一起升高。
所以要看的是两个 CER 的**组合**。

## 同一句文本的三方对照

文本：`今天天气好安逸哦，我们出去耍一哈嘛。`

| 音频 | 普通话 ASR 回读 | 川话 ASR 回读 | CER(base) | CER(ft) |
|---|---|---|---|---|
| `base_std_mandarin_reading.wav`（原版模型·普通话提示音读川话文本） | 今天天气好哎哟我们出去耍一下嘛 | 今天天气好哎呦我们出去耍一哈嘛 | 0.250 | 0.188 |
| `base_zeroshot_sichuan.wav`（原版模型·川话提示音零样本克隆） | 今天天气好哎哟我们出去耍一下嘛 | 今天天气好哎哟，我们出去耍一哈嘛 | 0.250 | 0.188 |
| `sft_female_01.wav`（微调模型·成都女声） | 今天天气好安逸哦我们出去耍一哈嘛 | 今天天气好安逸哦，我们出去耍一哈嘛。 | 0.000 | 0.000 |

微调模型把「安逸」「一哈」读对了（两个识别器都 0 错），原版模型两种提示音都读成
「哎哟……一下」——这不是口音差异，是**读错字**：原版模型没见过川话口语词。
这是本次微调最直接的效果证据：同一句话，原版 25% 字错，微调 0% 字错。

### 一个自发的方言特征

`sft_avg_02.wav` 的文本是「他屋头那个猫儿又跑到房顶上去了」，普通话识别器如实回读成
「他屋头**嘞个**猫儿又跑到房顶上去了」。文本写的是「那个」，模型读成了「嘞个」——
这是成都话特有的指示代词读音，训练数据里出现过，模型把它泛化到了没见过的句子上。
川话识别器因为见过这种读法，反而把它规范化回了「那个」。

## 已知缺陷

`sft_avg_01.wav`「搞归一了」被读成「搞鬼一楼」：`归`（guī）读成了 `鬼`（guǐ），
`了`（le）读成了 `楼`（lóu）。这是训练语料里「归一」出现次数太少导致的，属于**词级读音错误**，
而且**是偶发的**——重新采样后同一句能读对（`src/verify_service.py` 里跑通过 CER 0.000）。
`归一` 在 9.12 小时语料里只出现几十次，属于长尾。

## 怎么听

```bash
for f in *.wav; do echo "== $f"; ffplay -nodisp -autoexit "$f"; done
```

三组重点对照：

1. `sft_female_01.wav` vs `base_std_mandarin_reading.wav`：同一句川话文本，
   微调模型 vs 原版模型标准朗读。听「安逸」「一哈」「耍」的读音。
2. `sft_female_01.wav` vs `base_zeroshot_sichuan.wav`：微调模型 vs 零样本克隆。
   后者回读 CER 0.250，是合成不稳定，不是口音更浓。
3. `sft_female_02.wav` vs `mandarin_01.wav`：川话 vs 普通话，确认普通话能力没丢。
